Agentic Workflows
Lesson 1 of 5

What Is an AI Agent?

You've probably used a chatbot: you type a question, and it types back an answer. Under the hood, that's a large language model, or LLM — a program trained on huge amounts of text that has learned to predict what words should come next, well enough to hold a convincing conversation. Give it a prompt, and it gives you a reply. One turn, then it's done.

An AI agent is built on top of an LLM, but it does more than talk — it acts. Instead of only producing a reply, an agent can look things up, run a calculation, write and run code, or trigger a real action on your behalf, and then use whatever it finds to decide what to do next. It doesn't just answer once; it works.

Key idea

An agentic workflow is a process where the AI doesn't just answer a question once, but works through a task in steps — checking its own progress, adjusting when something doesn't go as planned, and continuing until the goal is actually met.

Compare "What's my flight status?" to "Rebook my flight if it's delayed." The first is a single question with a single answer. The second requires the system to check the status, reason about what that result means, and then decide whether to take a further action — rebooking. That extra loop of checking, deciding, and acting is exactly what the rest of this course is about.

Lesson 2 of 5

How Agents Take Action

An agent's actions come from tools — functions or services it's allowed to call, such as a web search, a calculator, a piece of code it can run, a database it can query, or an email it can send. The language model itself still can't do any of these things directly; what it can do is decide, based on the situation, which tool to use and when.

That decision-making follows a simple loop that repeats until the task is finished:

  • Observe — take in the current situation: the user's request, and the result of whatever happened last.
  • Decide — reason about what needs to happen next to make progress.
  • Act — call a tool, or produce a final answer if nothing more is needed.

Then the loop starts again with whatever the tool returned. Ask an agent to summarize the latest news on a topic, and it might decide to search the web (act), read through the results (observe), decide it needs a second, more specific search (decide, act again), and only once it has enough to work with does it write the summary.

Key idea

The important part isn't the tools themselves — it's that the model decides which one to use and when, based on its own reasoning, rather than a programmer hard-coding every possible case in advance.

Lesson 3 of 5

Planning Multi-Step Tasks

Real goals are rarely one step. "Plan a weekend trip to Kyoto" isn't a single lookup — it means checking flights, checking hotel availability, checking the weather, and then pulling all of that into an itinerary. Some of those steps depend on the results of earlier ones: there's no point comparing hotels near the airport until you know which flights are actually available.

To handle this, an agent typically drafts a rough plan up front — a rough sequence of sub-tasks — and then works through it one step at a time. Crucially, that plan isn't fixed: if a step turns out to be impossible (the flights on the planned dates are sold out), the agent revises the remaining plan around that new information, rather than failing outright.

Key idea

This is a real shift from older, scripted software. A traditional program follows a decision tree a developer wrote out in advance for every case. An agent forms its own plan for the specific task in front of it, and reworks that plan as things change along the way.

This is also why the "act, then observe the result" loop from the last lesson matters so much for planning: each action doesn't just move the task forward, it also tells the agent whether the rest of its plan still makes sense.

Lesson 4 of 5

Memory & Context

An LLM can only "see" a limited amount of text at once — its context window. Everything relevant to the task — the original instructions, the steps taken so far, the results of any tool calls — has to fit inside that window. On a long, multi-step task, that adds up fast.

So instead of keeping every raw detail forever, an agent needs to manage what it remembers: condensing progress into notes, keeping only what's still relevant, and setting aside the rest. This is usually split into two kinds of memory:

  • Short-term memory — what's happened so far within the current task, like which searches it already ran and what they turned up.
  • Long-term memory — information saved outside the conversation itself, often in an external store the agent can search back through, so it can be recalled in a future session (for example, a user's stated preferences from last week).
Key idea

Without memory, an agent tends to repeat work it's already done, contradict itself, or simply lose track of the goal partway through a long task. Good memory management is what lets an agent stay coherent over many steps, not just one.

Lesson 5 of 5

Agents Working Together

Some tasks are big enough that one agent handling everything does a mediocre job of all of it — much like one person can't be an expert researcher, coder, and editor all at once. The common answer is to split the work across multiple specialized agents that each focus on one part of the job.

A typical pattern has one agent acting as a coordinator: it breaks the overall goal into pieces, hands each piece to an agent suited for it, and then combines their results into a final answer. A research task, for instance, might involve a research agent that gathers sources, a writing agent that drafts a report from them, and a reviewing agent that checks the draft before it's returned.

This kind of multi-agent teamwork already shows up in practice:

  • Coding assistants that plan a change, write the code, then run and check the tests in a loop.
  • Customer support systems that route different kinds of questions to different specialist agents.
  • Research assistants that gather sources with one agent and draft a report with another.
Key idea

Put together, what an agent is, how it takes action, how it plans, how it remembers, and how agents can team up — that's the full picture of what people mean by an agentic workflow: a system that goes from a request to a finished result through its own reasoning, not a fixed script.
